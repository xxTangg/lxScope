# 销售运营中心业务规则

## 系统定位

销售总台是多客户龙信系统的运营控制面，不直接承载普通用户的聊天或业务操作。它管理客户系统、系统级 Token 额度、充值订单、发布包和远程升级。

身份映射固定为 `tenant -> customer -> system`。`tenant` 是龙信应用中的
租户权限边界，`customer` 是销售总台客户档案，`system` 是被交付的实例。
创建或修改 Customer 时，服务端拒绝重复的 tenant/customer/system 映射；
旧数据在读取时以 `systemId`（缺失时以 Customer ID）作为兼容 tenant 映射，
新数据应显式保存 `tenantId`。

## 用户权限与申请影响

龙信 AI 助手的用户角色在客户系统内生效：

| 角色     | 看到管理中心       | 可做的动作                                       | 对销售总台的直接影响                                                             |
| -------- | ------------------ | ------------------------------------------------ | -------------------------------------------------------------------------------- |
| 普通用户 | 否                 | 在客户端提交普通订阅/额度申请                    | 申请先落客户系统本地订单；不会自动生成销售总台订单                               |
| 管理员   | 是                 | 审批本地用户申请、查看管理中心、发起系统充值申请 | 审批会消耗客户系统本地系统账户额度；系统余额不足时管理员可向销售总台提交充值申请 |
| 销售人员 | 不属于客户用户角色 | 管理客户、审核销售订单、签发充值码、发布和升级   | 直接改变销售总台订单、客户额度和交付状态                                         |

关键结论：销售总台当前只接收“客户系统级”的申请和汇总报告，不接收普通用户身份、管理员身份或每一笔客户端普通用户申请。普通用户申请只有在管理员审批并消耗系统账户额度、触发系统余额不足后的后续动作中，才会间接影响销售总台。

## 充值链路

1. 普通用户在客户系统提交申请，生成客户系统本地 `pending` 订单。
2. 客户管理员在管理中心批准或拒绝本地申请。
3. 批准时从客户系统系统账户的 Token 池分配额度；额度不足则批准失败或需要先补充系统额度。
4. 客户管理员可发起系统级充值申请，客户系统携带 `system_id、amount、note、requested_at` 调用销售总台的 `/api/v1/integration/recharge-requests`。
5. 销售人员在销售总台审核申请：拒绝则结束；批准则按金额生成并签名充值码。
6. 客户系统定时轮询已批准订单，自动兑换充值码，再调用确认接口。
7. 客户系统定时上报 `pool_tokens、total_recharged、cumulative_consumed、cumulative_credits、app_version`；销售总台据此展示汇总运营数据。

销售总台不应根据客户端上报的 `totalRecharged` 直接重复计费；该字段是系统侧累计充值快照，订单金额和订单状态才是销售交易依据。

## 升级链路

1. 销售人员上传 `app` 或 `core` 的 `.tar.gz` 包。
2. 销售 API 校验路径安全性、`manifest.json`、包类型、版本和必要文件，并计算 SHA-256。
3. 发布包保存于数据目录的 `releases/`，不写入源码目录。
4. 销售人员选择已配置地址的客户系统，销售中心调用 `/integration/sales/v1/upgrades/{artifact_type}`。
5. 客户系统从销售中心拉取最新包，备份、解包、应用、重启并做健康检查；失败时回滚。
6. 销售中心记录每个目标的结果，并二次调用 ping/版本确认。

销售中心升级和管理中心升级解决的是同一个“应用/运行时升级”问题，但前者负责多客户分发与编排，后者负责单个客户系统实际执行。canonical 类型 `core` 表示 AgentScope 平台整体升级，`app` 表示龙信业务应用升级。

## 必须保留的安全规则

- 客户接口只接受 Bearer Token；销售人员接口只接受 HttpOnly Cookie。
- 充值码私钥只在销售中心保存，客户侧只保存公钥并验签。
- 普通用户权限必须由后端再次校验，不能只依赖前端是否显示管理中心。
- 发布包必须阻止绝对路径和 `..` 穿越，且限制文件数量与大小。
- 生产环境禁用默认密码，数据目录与密钥目录不能提交到 Git。
