# 独立建设与生产化计划

## 阶段一：独立业务骨架（已完成）

- `sales-console` 是独立项目，不引用历史销售总台代码、数据库、进程或部署目录。
- 前端采用 AgentScope 的 React、TypeScript、pnpm 工具链。
- 后端独立实现销售人员 Cookie 鉴权、客户 Bearer 鉴权、业务规则和升级编排。
- Docker 部署使用 PostgreSQL 保存客户、订单、报告、配置和审计数据；直接本地开发且未配置 `DATABASE_URL` 时仍可使用 JSON 文件仓库，便于联调。
- 客户系统只通过 `docs/API-CONTRACT.yaml` 定义的 API 接入新销售运营中心。

## 阶段二：新系统数据与接口固化

- 固化 `docs/API-CONTRACT.yaml`，由前后端共同评审后生成类型和接口测试。
- 新系统建立自己的客户、订单、报告、设置、发布和审计数据模型。
- 如需保留历史业务数据，只允许通过一次性、可审计的离线导入完成；导入完成后不再依赖数据来源系统。
- 使用测试客户系统验证充值申请、审批、轮询、确认、报告、充值码、升级包下载和远程升级。
- 对普通用户申请、管理员审批、系统余额不足三条链路分别做验收。

## 阶段三：生产化增强

- PostgreSQL：当前先通过兼容存储层接入独立数据库；正式生产前将客户、订单、报告、发布、升级任务、审计拆分为独立表，并增加唯一约束和状态迁移约束。
- 队列：充值码交付、报告聚合、连接探测、升级任务改为可重试异步任务。
- 密钥：Ed25519 私钥迁移到受控密钥服务或受限挂载目录，增加轮换和公钥版本。
- 权限：销售管理员、运营、只读审计等角色细分；所有写操作带操作者、来源 IP 和 request ID。
- 部署：TLS、反向代理、备份、恢复演练、日志脱敏、告警和升级灰度。

## 独立运行原则

- 新销售运营中心是唯一业务管理入口，前端、API、数据目录和发布目录均由本项目负责。
- 禁止新代码直接导入、读取或调用历史销售总台的内部实现。
- 客户系统与新销售运营中心之间只通过稳定 API 通信；客户端协议是外部接口，不等同于对历史销售总台的依赖。
- 发布后不进行新旧系统双写，不共享订单号生成器、额度账本或会话状态。
