# 销售运营后台前端精简报告

## 1. 改造前页面问题清单

基线检查日期：2026-10-28。只检查 `apps/admin-web`，API 与后端保持只读。

1. 一级导航有 8 项。充值审核、对账、余额预警属于同一财务工作流却分成三个入口；总部公钥和系统设置也各占一个入口。
2. 工作总览有四张 KPI 卡、充值图表、客户额度分布、最近动态、系统概况表和待办区。余额预警没有进入首页待办，升级异常也没有汇总入口。
3. 客户页同时显示创建表单、8 列客户表和整块编辑详情。没有客户搜索/状态筛选，低频连接字段挤占列表宽度；选中详情出现在列表下方，查看后需要继续向下滚动。
4. 充值申请、用量对账和余额预警各有独立标题/面板，切换上下文需要返回侧栏；充值记录主要藏在客户详情中。
5. 升级页先选目标、再浏览两个升级包，步骤顺序不清晰；执行中反馈有限，失败结果没有就地重试动作。
6. 汇率、密码、公钥和审计分散在系统设置与总部公钥两个页面；卡片嵌套和标题重复增加视觉层级。
7. `body` 有 1120px 最小宽度，客户详情、表格和双栏布局在常见桌面宽度或浏览器缩放时可能产生横向滚动。

## 4. 修改清单

- `src/App.tsx`、`src/types.ts`：一级导航和页面状态改为 5 项，财务/系统页由页签承载原页面。
- `src/features/dashboard/Overview.tsx`：保留现有数据来源，压缩 KPI 与列表，汇总余额和升级关注项并提供导航入口。
- `src/features/customers/Customers.tsx`：增加搜索/状态筛选、创建弹层、核心字段列表和右侧详情抽屉；详情分资料/充值/用量/技术配置页签。
- `src/features/recharge/*`：通过财务页签重用申请、充值记录、对账、预警原功能。
- `src/features/upgrades/Upgrades.tsx`：按发布、目标、执行反馈组织原有上传/升级动作。
- `src/features/settings/*`：通过系统管理页签合并汇率、密码、公钥和审计。
- `src/styles.css`、必要的共享 UI 组件：统一标题、页签、抽屉、表单/表格密度、响应式和焦点样式。
- `vite.config.ts`、`Dockerfile.dev` 与项目根目录 `compose.yaml`：默认 `admin-web` 容器改为运行 Vite 开发服务，挂载前端源码并启用文件轮询，API 代理走 Compose 内的 `sales-api`；旧静态 Dockerfile 保留但不再是默认 Compose 启动路径。
- 本报告与验证截图：记录改造前后入口映射和页面回归证据。

## 6. 验收结果

### 检查结果

- 当前执行环境为 Node.js 24.16.0、pnpm 9.15.9；仓库声明 Node.js `>=20 <21`，因此 pnpm 输出 engine warning。本轮构建和 lint 仍通过；交付前应在 Node 20 下再执行一次。
- `pnpm --filter admin-web build`：通过；脚本先运行 `tsc -b` 类型检查，再执行 Vite 构建（1882 个模块）。
- `pnpm --filter admin-web lint`：通过。
- Prettier 对本次修改文件执行 `--check`：通过。
- `git diff --check -- apps/admin-web`：通过；仅报告 Git 的 LF/CRLF 工作区转换提示。
- `docker compose config --quiet`：通过；`docker compose build admin-web`：通过，开发容器基于 Node 20。
- 容器运行检查：44101 返回 Vite 客户端，`/src/App.tsx` 含 5 项新导航；API 健康检查 200。
- 范围核对：前端实现仍在 `apps/admin-web`；为满足容器热重载启动要求，本次追加修改 `compose.yaml`，没有修改 API 代码或数据库结构。

### 浏览器功能回归

- 侧栏：确认恰为 5 个一级入口。
- 客户：创建隔离测试客户，验证搜索、状态筛选、抽屉、资料/充值/用量/技术配置页签；创建只发生在本机临时 JSON 测试数据中。
- 财务：验证充值申请、按客户查询充值记录、用量对账和余额预警页签可达。
- 系统管理：验证业务参数、安全与公钥、审计记录页签可达并可读取现有数据。
- 升级：验证版本发布、目标客户、执行结果流程和高级配置展开；没有上传升级包或向客户发起远程升级。
- Token 轮换、密码重置、充值审批等有副作用操作未在真实业务数据上执行；现有确认流程和原 API 调用保留。
- 本轮没有更改对外 API、认证、签名、数据库结构或业务规则。
- Compose 默认启动现在使用带源码挂载的 Vite 容器；容器仍代理到现有 `sales-api`，本次没有执行业务写入。`docker compose up -d admin-web` 会重建/启动开发前端，并可能按 Compose 配置重建 API 容器；PostgreSQL 数据卷未重建。

### 已知限制

- 后端升级接口当前为同步调用，前端只能显示请求期间的处理中状态；缺少服务端任务 ID/事件流，因此无法提供可靠的实时百分比或跨页面持久任务历史。本次没有虚构进度或新增后端协议。
- 低于 827px 的窄屏、实际浏览器缩放比例和生产数据下的权限组合需要在目标部署环境继续验收。
- 截图留在任务对话的浏览器回归记录中，没有作为仓库图片文件提交。
