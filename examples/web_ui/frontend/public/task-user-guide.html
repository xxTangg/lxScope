模板设计理念

Task 模板把常见业务任务固化为有输入、有步骤、有输出要求的流程。它优先复用经过定义的业务路径，帮助用户知道要准备什么资料、哪些节点会调用工具、结果需要怎样复核。

有边界的流程

必填信息、步骤顺序、能力依赖、失败处理和最终输出要求在模板中说明。模板实例化使用服务端已定义的步骤，不会调用 AI Planner 自动改写流程。

保留必要的人为判断

“草稿”“待核实”“需人工复核”是有意保留的业务状态。模型产出的解释不能代替正式规则源、审批记录或人工签字。

快速开始

  1. 在 Task 页面打开“业务模板”，选择适合的场景。先检查适用范围、必需输入、步骤和能力依赖。
  2. 点击“使用此模板”创建任务，补齐必填资料。只关联当前用户获准访问的知识库和来源。
  3. 运行任务。Task 会先做运行前能力检查；若工具、接口、权限或数据源不满足，先按提示修正。
  4. 在“执行情报”中查看执行轨迹、工具调用、引用/证据、产物和待复核项。对关键结果进行人工确认后再进入正式业务系统。
单击模板行选择模板；右侧的小问号（?）会在新页打开本手册对应业务章节，当前 Task 页面保持不变。

九个业务场景

场景版本以当前服务端模板为准；部署环境可能使用不同版本。模板卡片展示实际版本号。

01项目立项 s01_project_init · v2

整理项目立项信息，检索相似项目与适用规则，形成待核验的立项建议。

准备资料项目名称、背景/目标/范围；行业和拟评审范围可选。主要过程识别项目字段 → 检索相似项目 → 核对规则 → 整理立项建议 → 核实事实。预期结果立项信息卡、相似项目线索、规则核对来源和待人工核实项。边界建议不是审批结论；不会自动写入项目台账。

02项目策划 s02_project_planning · v2

根据项目材料和经批准的策划模板生成大纲与初稿，并核验可追溯引用。

准备资料项目名称、项目资料、获准的策划模板和适用要求。主要过程读取项目资料 → 选择/核对策划模板 → 生成策划大纲和正文 → 校验引用 → 人工复核。预期结果大纲、策划草稿、来源证据和待复核清单。边界示例/未验证数据不能当作真实结论；资料不足时保留待补字段。

03专家智能匹配 s03_expert_matching · v3

按项目专业要求对用户提供的结构化候选专家资料做初步排序，并整理回避信息。

准备资料项目名称、专业领域、项目简介、候选专家结构化记录。主要过程提取项目要求 → 读取候选数据 → 检查候选记录和回避字段 → 按专业字段匹配排序 → 收集人工复核。预期结果候选匹配结果、输入记录的回避信息、数据质量问题和人工确认项。边界当前版本不查询正式专家库，不证明实际利益冲突状态，也不构成正式推荐或聘任意见。

04会前准备 s04_meeting_preparation · v3

依据会议参数准备议程、物料、费用计算和会前检查，为授权通知流程准备材料。

准备资料会议主题、日期、参会人数、用户提供的费用标准和修改意见。主要过程生成会务资料 → 核算费用 → 检查会前要素 → 收集修改 → 整理通知草稿。预期结果会前材料草稿、费用计算依据、检查结果和通知准备状态。边界需要真实会议系统、通知权限和授权确认时，应先完成集成与审批；草稿不能视为已通知。

05会议召开与纪要 s05_meeting_minutes · v3

处理用户提供的已转写会议文本，生成议题摘要和待办草稿，并收集人工修订。

准备资料会议标识、已获准使用的转写文本。主要过程读取转写文本 → 整理议题和行动项 → 生成纪要草稿 → 汇总修订意见。预期结果议题摘要、待办列表、修改记录和转写来源状态。边界当前版本不处理原始音频、不执行 ASR；纪要需会后人工确认和发布。

06意见整理 s06_opinion_processing · v3

按业务方提供的分类规则整理已识别文本、去重并生成待复核汇总。

准备资料项目名称、意见文本记录、分类规则。主要过程读取已识别意见文本 → 分类、汇总和去重 → 标记不确定项 → 人工复核 → 生成汇总草稿。预期结果分类统计、意见摘要、疑似重复项和人工待办清单。边界当前版本不读取图片、不执行 OCR；分类准确性受输入规则和文本质量影响。

07报告生成 s07_report_generation · v4

仅基于当前用户获准资料生成评审报告草稿，对引用来源做确定性核验。

准备资料项目名称、获准资料标识、必需章节；适用规则标识可选。主要过程检索授权资料并留证 → 按章节生成草稿 → 校验引用编号、来源身份和逐字摘录 → 检查结构/规则 → 人工复核。预期结果含引用映射、完整性/一致性检查及未解决事项的报告草稿。边界引用存在不代表其语义充分；最终内容、适用规则和合规签字仍由真实审核流程确认。

08归档移交 s08_archive_transfer · v3

核对用户提交的归档文件元数据和必需项，输出待移交清单。

准备资料项目标识、文件元数据清单、归档类别、必需元数据字段。主要过程规范文件元数据 → 核对归档要求 → 汇总缺项 → 生成待移交清单。预期结果文件清单、元数据完整性报告、缺项和待移交状态。边界当前版本不读取文件内容，也不写入档案系统；需授权的系统写入应另经审批与验收。

09报销结算 s09_expense_settlement · v3

依据用户提供的结构化票据信息和费用规则核算报销草稿。

准备资料项目标识、结构化票据记录、费用类别和规则。主要过程读取结构化票据 → 检查任务内重复 → 应用规则核算 → 整理报销草稿 → 标记提交前条件。预期结果票据摘要、重复项状态、规则核算和待提交草稿。边界当前版本不验真、不执行审批、不提交 ERP；真实提交需要实际权限、审批证据和幂等控制。

知识沉淀是否体现？

有知识使用与单次运行证据能力，但不等同于自动写入长期知识库。Task 页面可以关联有权限的知识库；节点可以启用知识图谱；报告类流程可保存本次运行的来源快照、引用编号和校验结果。具体能否检索或生成图谱，取决于任务配置、工具能力、数据源和访问权限。

知识库检索

为任务选择知识库后，运行时可检索授权资料。结果中应保留来源信息，供执行情报查看和人工核对。

节点知识图谱

在流程节点中启用后，可在相应执行节点查看本次形成的图谱结果。它呈现本次任务的关系信息，不自动意味着已写回长期知识库。

长期知识沉淀需要明确的写入目标、内容筛选、来源与权限校验、人工审批、版本记录和撤回/更正机制。若页面没有显示知识库写入操作与回执，应将本次结果视为任务产物或运行证据，而非已完成知识入库。

执行情报：过程、结果和依据

执行情报提供任务运行后的观测入口。各标签页显示的资料取决于本次运行所返回的数据。

  • 执行轨迹：按步骤查看状态、时间、摘要、完整输出、错误和产物。
  • 智能分析：检查任务目标、自动拆解、执行策略和风险提示。
  • 工具：查看使用的工具/MCP、能力名称及可用性。
  • 产物：预览或下载本次生成的文件。

运行前能力检查会在执行前展示工具、接口兼容性、权限和真实业务数据源状态。它回答“当前配置是否具备运行条件”，不能替代业务规则合规判断。

合规、安全和操作检查：开发方案

这三类检查需要由服务端基于规则、权限、工具调用和审批记录得出结构化结果，再同步到执行情报。界面不能仅凭模型生成的“已合规”文字显示通过。

合规检查

在运行前、规则依赖步骤和最终输出处检查适用规则、授权来源、必需字段和证据引用。显示规则版本、命中项、证据和待核事项。

安全检查

在读取资料、调用工具和输出结果边界检查主体/租户权限、数据范围、敏感信息、凭据泄露和外部发送目标。权限或策略不可确认时阻断敏感操作。

操作是否合规验证

将动作分类为只读、内部修改、外部发送或不可逆操作；写入前核对审批证据、二次确认、幂等键和目标系统权限，记录执行回执。

状态呈现

使用“通过、未通过、待人工复核、未检查、检查中”。无规则或无证据时不得默认为通过；阻断项要说明责任步骤、理由及可采取的下一步。

当前 Task 已有运行前能力/权限/数据源检查和部分输出引用校验。以上三类统一检查面板与通用业务规则验证属于后续开发范围；在部署版本没有真实检查结果前，不能把截图示意或 AI 文本当作已完成校验。

常见问题

模板卡片显示“待校验工具”是什么意思？

模板定义了所需能力；运行前会结合当前会话检查工具和接口。模板存在不代表外部业务系统已经接通或授权。

知识图谱是否等于已沉淀知识？

不等于。图谱可呈现任务节点中的关系结果；只有在明确的授权写入、审批和回执流程完成后，才可称为长期知识库入库。

检查通过后可以直接提交正式业务结果吗？

不一定。能力检查只说明运行条件；具体审批、签字、对外通知或业务系统写入仍应依据真实权限和业务流程处理。

手册链接没有打开对应章节怎么办？

确认部署包包含 task-user-guide.html，且应用静态资源使用与应用一致的部署前缀；也可从手册目录按场景进入。
