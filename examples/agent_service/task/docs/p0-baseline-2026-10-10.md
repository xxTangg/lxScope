## 文件与执行链路核对

- Task 实现位于 `examples/agent_service/task/`。核心检查文件为 `_models.py`、`_service.py`、`_sop.py`、`_plan_validation.py`、`_router.py`、`_store.py`、`_redis_store.py`、`_postgres_store.py`、`_planner.py`、`_agentscope_planner.py` 和 `__init__.py`。
- Task Router 使用 `/tasks` 前缀，并通过既有 `get_current_user_id` 依赖取得用户。应用在 `examples/agent_service/main.py` 导入并注册 `task_router`，同时在应用状态中初始化 `TaskService`。当前仓库没有 `examples/agent_service/app.py`；方案中提到该文件与实际服务入口文件名不同。P0 无需改入口文件，新增 Task 路由可继续放在 `_router.py`。
- API 客户端是 `examples/web_ui/frontend/src/api/task.ts`。`src/api/index.ts` 已导出 `taskApi` 和当前 Task 类型；前端可以沿用 `taskApi`，新增模板专用类型直接从 `@/api/task` 导入，因而不需要修改共享 API 汇总文件。
- Task 页面位于 `examples/web_ui/frontend/src/pages/task/`。`index.tsx` 的自由创建路径调用 `taskApi.create()` 后调用 `generateTask()`；后者向 `/tasks/{task_id}/generate` 发请求。`task-flow-editor.tsx` 已支持四种现有步骤的添加、删除、编辑和重排，但没有模板必需步骤约束；“新增步骤”没有 8 步上限检查。
- 数据流：自由创建由 `CreateTaskRequest` 进入 `TaskService.create_task()`；有节点则直接保存为 active Task，无节点则存为 draft。自由规划单独通过 `/tasks/{task_id}/generate` 调用 Planner，生成结果经 `validate_task_plan()` 后保存。编辑通过 `PATCH /tasks/{task_id}` 进入 `update_task()` 并递增 revision。运行通过 `POST /tasks/{task_id}/runs` 进入 `create_run()`：先以当前 Task revision 和 nodes 建立 `TaskRunRecord` 快照并写入存储，再更新 Task 最近运行状态、排入后台执行。后台 `_advance_sop()` 使用 `_build_sop_engine()` 创建 `TaskSOPStep`，最后交给官方 `SOPEngine` 线性推进。
- 存储反序列化：内存 `TaskStore` 保存/复制 Pydantic `TaskRecord`；Redis 通过 `TaskRecord.model_validate_json()` 解析；Postgres 通过 `TaskRecord.model_validate(payload)` 解析。因此后续可选字段可采用默认值兼容旧 JSON，但仍需按方案在存储测试中证明。

## 现有能力与缺口

| 项目 | P0 观察 |
|---|---|
| 步骤类型与上限 | `StepType` 只有 `agent`、`tool`、`python`、`input`；`TaskPlanDraft`、`CreateTaskRequest`、`UpdateTaskRequest` 都限制最多 8 步。P1 应只用这四类和此上限。 |
| 直接建 Task / Planner | `create_task()` 接收已有 nodes，因此模板可绕过 Planner；`generate_task()` 是显式 AI 规划路径。当前前端自由创建默认走 Planner，模板入口必须独立实现。 |
| 保存与运行校验 | `update_task()` 目前保存请求节点并递增 revision，没有模板来源、强制步骤或统一结构校验。`create_run()` 检查 Task active 且至少一个节点，然后先保存 Run 快照并排队；没有模板能力/输入/强制步骤预检。 |
| 规划校验 | `_plan_validation.py` 的 `validate_task_plan()` 默认要求末节点为 Agent；它适用于现有生成规划，不能不加区分地当作所有模板的运行校验。 |
| 模板支持 | 当前没有模板 Registry、模板 JSON、模板列表/详情/实例化/预检 API，也没有模板来源版本或服务端必需节点绑定。Task Router 可扩展且已有身份依赖。 |
| 编辑器保护 | 现有流程编辑器允许编辑全部节点、删除节点和重排；未提供模板 required/editable 规则，也未实现 8 步上限提示。 |
| 业务能力真实性 | Task 有一般 Tool 发现和调用路径，但未发现九场景的真实专家库、回避规则、业务评分、审批权限、ERP/档案/通知写入或外部回执契约。ToolStep 本身不代表这些业务接口已接通。 |
| 执行模型边界 | 当前 Task SOP 是线性步骤执行。`input` 是 Task 用户问答，不是企业审批；未发现 DAG/条件分支/持久化外部回执等待协议。不得将这些能力描述为现有支持。 |
