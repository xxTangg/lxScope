# Task 九场景能力矩阵（P1）

范围：P1 只定义模板数据与能力依赖，不表示业务工具已经接通，也不触发 Task。所有场景当前均为**设计中**；后续可运行状态必须由真实 Tool、输入约束和权限预检动态计算，不能从模板静态字段推断。

现有 Task 仅支持线性 `agent`、`tool`、`python`、`input` 步骤，单个流程最多 8 步。此批模板使用 `agent`、`tool`、`input`，没有新增 StepType，也没有用 `input` 冒充审批或回执等待。所有 Agent 步骤还需要调用方选定的 Task 会话具备可用模型；这是运行上下文前置条件，不代表业务 Tool 已接通。

| ID / 场景 | 当前逻辑步骤 | 主要能力依赖（尚未核验接通） | 明确不支持或阻断边界 |
|---|---:|---|---|
| S01 项目立项 | 7 | 相似项目检索、立项规则、项目读取权限 | 无项目库/规则契约时只可设计预览；不写项目台账。 |
| S02 项目策划 | 7 | 策划模板、资料检索、引用核验、文档输出 | 无模板/引用契约时不声称引用已核验；输出是草稿。 |
| S03 专家智能匹配 | 8 | 专家库、回避规则、评分算法 | 上述数据与契约未提供；人工审批身份和权限协议不支持；不得生成假专家或假回避结果。 |
| S04 会前准备 | 7 | 费用计算、物料生成与检查、通知工具 | 真实审批、通知授权、幂等发送与外部回执等待不支持；必须阻断发送。 |
| S05 会议召开与纪要 | 6 | 音频资产访问、ASR、纪要输出 | 无 ASR 时不得编造转写；InputStep 仅收集复核意见，不是正式签发。 |
| S06 意见整理 | 7 | 图片资产访问、OCR/手写识别、分类与导出 | 无识别/分类契约时保留待处理；低置信文字不得猜测。 |
| S07 报告生成 | 8 | RAG、引用核验、一致性和合规规则、文档输出 | 无检查工具不得标记通过；正式审核签字不支持，结果保持草稿。 |
| S08 归档移交 | 6 | 文档元数据提取、完整性规则、档案系统接口 | 写入权限、人工授权、幂等写入和外部回执等待不支持；必须阻断归档写入。 |
| S09 报销结算 | 6 | 发票 OCR/验真/去重、费用规则、ERP 接口 | 审批、ERP 权限、幂等提交和财务回执等待不支持；必须阻断提交。 |

模板中的 `capability_key` 是龙信 Scope Task 的逻辑能力标识，不是已注册的 AgentScope Tool 名称。P3 才能按当前会话实际可用工具做绑定；没有绑定时不得把逻辑能力名直接作为 Tool 名称执行。模板参数只使用 `{{user_input}}`、`{{previous_output}}` 等方案允许的简单引用，不包含脚本、条件表达式、内部 URL、密钥或真实业务样本。

S03 的回避校验、评分和人工确认是业务必需步骤。模板将其列为必需步骤，但 P4 才实现服务端强制节点保护；P1 的 JSON 元数据本身不是安全边界。S04/S08/S09 中的外部副作用步骤只有在真实接口、权限、授权和幂等机制经过后续阶段验收后才可解除阻断。
