# Longxin AgentScope 销售系统对接接口与请求体

> 本文档供销售总部开发和联调使用，请严格按字段名、字段类型和状态值实现。

## 1. 当前连接信息

| 项目 | 值 |
|---|---|
| 销售总部地址 | `http://192.168.31.197:44100` |
| 本地系统地址 | `http://192.168.31.182:18201` |
| `system_id` | `456` |
| 销售总部机器接口前缀 | `/api/v1/integration` |
| 本地反向接口前缀 | `/integration/sales/v1` |

Token、密码、私钥和充值码禁止写入本文档或普通日志，使用占位符表示。

## 2. 公共请求头

本地系统调用销售总部：

```http
Authorization: Bearer <customer-api-token>
Content-Type: application/json
X-Request-ID: <唯一请求ID>
Idempotency-Key: <唯一幂等键>
```

销售总部调用本地系统：

```http
Authorization: Bearer <customer-api-token>
X-Request-ID: <唯一请求ID>
```

要求：

- `X-Request-ID` 必须在响应中原样返回；
- 会改变状态的 POST 必须支持 `Idempotency-Key`；
- 相同幂等键重试不能重复创建订单、重复兑换或重复 ACK；
- 金额必须是字符串并保留两位小数，例如 `"0.01"`；
- 时间必须是带时区的 ISO 8601，例如 `2026-09-16T02:22:26Z`。

## 3. 线上充值接口

### 3.1 本地提交充值申请

```http
POST http://192.168.31.197:44100/api/v1/integration/recharge-requests
```

请求体：

```json
{
  "system_id": "456",
  "amount": "0.01",
  "note": "线上充值",
  "requested_at": "2026-09-16T02:22:26Z"
}
```

成功响应必须包含：

```json
{
  "order_id": "ord_01J...",
  "system_id": "456",
  "status": "pending",
  "delivery_status": "not_delivered",
  "request_id": "req_01J..."
}
```

`order_id` 是后续审批、轮询和 ACK 使用的唯一订单号，必须保持不变。

### 3.2 销售员工审批订单

```http
POST http://192.168.31.197:44100/api/v1/recharge-requests/{order_id}/approve
Cookie: sh_session=<销售员工会话>
Content-Type: application/json
Idempotency-Key: <唯一幂等键>
X-Request-ID: <唯一请求ID>
```

请求体：

```json
{
  "amount": "0.01",
  "request_id": "req_01J...",
  "reason": "已确认到账"
}
```

`request_id` 必须填写原始充值申请的请求 ID，不能省略。

审批成功只表示销售总部生成了充值码，订单状态应为：

```text
status=approved
delivery_status=not_delivered
```

### 3.3 本地轮询已审批订单

```http
GET http://192.168.31.197:44100/api/v1/integration/recharge-requests/poll?system_id=456
Authorization: Bearer <customer-api-token>
X-Request-ID: <唯一请求ID>
Idempotency-Key: <唯一幂等键>
```

销售端必须返回下面格式。无订单时也必须返回 `orders: []`：

```json
{
  "orders": [
    {
      "order_id": "ord_01J...",
      "system_id": "456",
      "amount": "0.01",
      "tokens": 10,
      "status": "approved",
      "delivery_status": "not_delivered",
      "recharge_code": "LXRC2.<payload>.<signature>",
      "expires_at": "2026-09-16T03:22:26Z"
    }
  ],
  "request_id": "<与请求头 X-Request-ID 相同>"
}
```

字段要求：

| 字段 | 类型 | 要求 |
|---|---|---|
| `orders` | array | 必须存在；无订单返回空数组 |
| `order_id` | string | 必须与原始申请返回的订单号完全一致 |
| `system_id` | string | 必须为 `456` |
| `amount` | string | 两位小数，例如 `"0.01"` |
| `tokens` | integer | 必须大于 0 |
| `status` | string | 必须为 `approved` |
| `delivery_status` | string | 首次轮询必须为 `not_delivered` |
| `recharge_code` | string | 必须返回完整充值码，不能只返回 `code` |
| `expires_at` | string/null | 充值码有效期，建议返回 ISO 8601 时间 |
| `request_id` | string | 必须回显 `X-Request-ID` |

禁止返回这种格式：

```json
{
  "code": "<充值码>",
  "order_id": "另一个订单号",
  "request_id": "req_01J..."
}
```

不能把订单字段直接放在顶层，也不能根据金额 `0.01` 猜测订单。

### 3.4 充值码结构

充值码至少要绑定以下业务字段：

```json
{
  "system_id": "456",
  "amount": "0.01",
  "tokens": 10,
  "version": "1",
  "order_id": "ord_01J...",
  "nonce": "唯一随机值",
  "issued_at": "2026-09-16T02:30:00Z",
  "signature": "签名值"
}
```

当前本地联调代码识别的外层格式：

```text
LXRC2.<Base64URL编码的Payload>.<Signature>
```

原设计文档要求销售总部使用 Ed25519 公钥验签；当前本地示例代码使用 `LONGXIN_RECHARGE_CODE_SECRET` 做 HMAC-SHA256 验签。双方必须先确认统一的签名算法，不能只修改字段名。

### 3.5 本地兑换充值码

这是本地系统内部接口，销售端不直接调用：

```http
POST http://192.168.31.182:18201/admin/quota/redeem-code
Authorization: Bearer <本地管理员JWT>
Content-Type: application/json
```

请求体：

```json
{
  "code": "LXRC2.<payload>.<signature>",
  "confirm": true
}
```

本地会校验签名、`system_id`、金额、Token 数量、订单号和 nonce，并写入额度账本。

### 3.6 本地兑换后 ACK

```http
POST http://192.168.31.197:44100/api/v1/integration/recharge-requests/{order_id}/ack
Authorization: Bearer <customer-api-token>
Content-Type: application/json
Idempotency-Key: <唯一幂等键>
X-Request-ID: <唯一请求ID>
```

请求体：

```json
{
  "operation_id": "op_01J...",
  "system_id": "456",
  "redemption_operation_id": "op-redeem-01J...",
  "ledger_id": "led_01J..."
}
```

销售端收到有效 ACK 后，必须把原订单更新为：

```json
{
  "order_id": "ord_01J...",
  "status": "approved",
  "delivery_status": "delivered",
  "request_id": "req_01J..."
}
```

## 4. 用量上报接口

```http
POST http://192.168.31.197:44100/api/v1/integration/usage-reports
Authorization: Bearer <customer-api-token>
Content-Type: application/json
Idempotency-Key: <唯一幂等键>
```

请求体：

```json
{
  "system_id": "456",

  "cumulative_consumed": 1250000,
  "cumulative_credits": 5200000,

```

成功响应：

```json
{
  "report_id": "report_01J...",
  "system_id": "456",
  "accepted": true,
  "reported_at": "2026-09-16T02:30:01Z",

  "cumulative_credits_delta": 1000,
  "request_id": "<与请求头 X-Request-ID 相同>"
}
```

## 5. 双向连接验证

销售总部验证客户 Token：

```http
POST http://192.168.31.197:44100/api/v1/integration/verify-connection
Authorization: Bearer <customer-api-token>
Content-Type: application/json
X-Request-ID: <唯一请求ID>
Idempotency-Key: <唯一幂等键>
```

请求体：

```json
{}
```

销售总部随后请求本地 Ping：

```http
POST http://192.168.31.182:18201/integration/sales/v1/ping
Authorization: Bearer <customer-api-token>
X-Request-ID: <唯一请求ID>
```

本地 Ping 响应：

```json
{
  "ok": true,
  "system_id": "456",
  "system_name": "Longxin AgentScope",
  "app_version": "3.8.1",
  "core_version": "unknown",
  "checked_at": "2026-09-16T02:30:01Z",
  "request_id": "<与请求头 X-Request-ID 相同>"
}
```

## 6. 当前 `0.01` 订单联调结论

本地最新订单仍是 `pending / not_delivered`。销售端当前轮询返回顶层 `code、order_id、request_id`，没有 `orders` 数组，而且返回订单号与本地订单号不一致。

请先修正第 3.3 节轮询响应。格式修正后，本地系统会自动轮询；收到匹配订单后校验充值码、增加额度并发送 ACK，销售端再把 `delivery_status` 更新为 `delivered`。
