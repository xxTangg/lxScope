# 龙信系统管理员端功能迁移清单（AgentScope 适配版）

> 文档状态：Draft 0.1.0  
> 编写日期：2026-09-15  
> 适用代码库：`D:/agentscope_lx/lxScope`  
> 配套接口合同：[管理员端与销售系统 API 接口设计](./管理员端与销售系统API接口设计.md)

## 1. 使用说明

本清单把 `龙信系统-管理员端功能说明与技术框架迁移方案.md` 中的功能拆成可执行的迁移任务，并按当前 AgentScope 代码结构重新分配后端、前端、存储、销售系统对接和测试责任。

参考文档只作为业务需求输入；本项目的现有代码、认证方式、依赖注入、API 返回约定和资源所有权规则优先作为实现约束。

本清单中的 `[ ]` 表示尚未在当前 AgentScope 仓库实现；完成一个条目必须同时满足接口、权限、数据、审计、测试和前端联调要求，不能只完成页面或只完成数据库表。

### 1.1 优先级

| 优先级 | 含义 | 说明 |
|---|---|---|
| P0 | 基础阻塞项 | 不完成则不能上线任何管理员功能，例如身份、权限、幂等、审计基础设施 |
| P1 | 首次可用版本 | 企业管理员、配额、充值、连接验证和必要安全能力 |
| P2 | 生产运营能力 | 模型、技能、插件、升级、备份和审计详情 |
| P3 | 后续增强 | 工作流高级管理、细粒度总部角色、Token scope 拆分等 |

### 1.2 完成定义

每个迁移功能完成时必须检查：

- [ ] 后端 Pydantic 请求/响应模型已定义，OpenAPI 能生成完整字段；
- [ ] API router、service、store/adapter 分层完成，router 不直接操作 Redis/SQL/HTTP；
- [ ] 未登录、普通用户、管理员、无效客户 Token 的权限测试已完成；
- [ ] 关键变更有事务或等价的幂等机制；
- [ ] 高风险操作有 `operation_id`、审计事件和超时后的 `unknown` 处理；
- [ ] 敏感字段已脱敏，密码、Token、API Key、私钥不进入响应和普通日志；
- [ ] 前端使用统一 `client.ts` 和 React Query，不直接在页面中 `fetch`；
- [ ] API 契约测试、前端构建和销售系统联调测试通过；
- [ ] 本清单、API 文档、TypeScript 类型和变更日志已同步。

## 2. 当前 AgentScope 适配原则

### 2.1 保留现有能力

当前通用 AgentScope 接口继续使用已有路径：

```text
/auth
/agent
/sessions
/credential
/knowledge_bases
/skill
/mcp
/schedule
/workspace
/health
```

不得为了管理员功能整体重命名这些接口或强行加 `/api/v1` 前缀，以免破坏当前 Web UI 和其他调用方。

### 2.2 新增产品能力的边界

| 能力 | 代码落点 | 首期策略 |
|---|---|---|
| 本地管理员 API | `examples/agent_service/admin_api.py`、`admin_service.py` | 应用层新增 `/admin` router |
| 本地账号/角色/套餐/账本 | `examples/agent_service/*_store.py` | 独立于通用 `StorageBase` 的产品存储抽象 |
| 销售总部 HTTP 客户端 | `examples/agent_service/sales_hub_client.py` | 应用层 adapter，统一超时、重试、幂等和脱敏 |
| 总部反向命令接收 | `examples/agent_service/sales_hub_api.py` | 新增 `/integration/sales/v1` router |
| 管理员前端 | `examples/web_ui/frontend/src/pages/admin/`、`api/admin.ts` | 复用现有 JWT、client、React Query 和布局 |
| AgentScope 通用资源 | `src/agentscope/app/_router/`、`StorageBase` | 首期不增加龙信业务字段和接口 |

装配位置为 `examples/agent_service/main.py`：创建服务实例、放入 `app.state`、注册 admin/sales routers。只有未来确认多个 AgentScope 产品都需要这套管理能力时，才考虑给 `create_app()` 增加可选 `extra_routers`/`extra_services` 扩展点。

### 2.3 统一接口路径

| 调用方 | canonical path | 认证 |
|---|---|---|
| 本地管理员浏览器 | `/admin/...` | 本地 JWT Bearer，要求 `role=admin` |
| 本地用户 | 现有 `/auth`、`/agent`、`/sessions` 等 | 本地 JWT Bearer |
| 销售总部 → 本地 | `/integration/sales/v1/...` | 客户专属 Bearer Token |
| 本地 → 销售总部 | `/api/v1/integration/...` | 客户专属 Bearer Token |
| 总部员工 | `/api/v1/auth`、`/api/v1/customers` 等 | 总部员工 JWT/Session |

旧文档中的 `/api/admin/*` 和 `/api/hub/*` 可以由网关做兼容转发，但业务代码只维护 canonical path。

## 4. M0：接口合同和运行基础

### 4.1 任务清单

- [ ] 固化本文件和配套 API 文档为首版接口合同。
- [ ] 所有新 router 使用 `APIRouter(prefix=..., tags=...)`、`Depends()` 和 `response_model`。
- [ ] 增加 `X-Request-ID` 生成/透传中间件或依赖。
- [ ] 增加 `Idempotency-Key` 校验、请求体摘要、结果缓存和过期策略。
- [ ] 统一 UTC 时间、非浮点金额字符串、非负整数 token 和不透明 ID。
- [ ] 统一新接口错误结构：`detail.code`、`detail.message`、`detail.fields`、`request_id`。
- [ ] 日志增加 actor、customer/system、operation/order、request 关联字段，敏感字段统一脱敏。
- [ ] 为 Redis 和 SQL 产品存储定义同构接口测试。
- [ ] 为销售系统 HTTP 客户端定义连接超时、读取超时、重试次数和 `unknown` 规则。
- [ ] 在 CI 中校验 OpenAPI、前端 TypeScript 类型和契约测试同步。

### 4.2 公共接口约定

所有有状态变化的接口必须支持：

```http
X-Request-ID: req_01J...
Idempotency-Key: idem_01J...
```

异步操作返回：

```json
{
  "operation_id": "op_01J...",
  "request_id": "req_01J...",
  "state": "pending",
  "result": null,
  "error": null
}
```

网络超时只能进入 `unknown`，不得自动补偿为成功或失败；重试必须复用同一个幂等键。

## 5. M1：身份、角色、会话和权限

### 5.1 迁移目标

当前 `examples/agent_service/auth.py` 已有 JWT 登录、注册、`/auth/me` 和 Redis 账号能力，但 `AuthUser` 只有 `id`/`username`，账号结构也不足以支持管理员管理。此阶段先完成身份基础，再开放其他管理员 API。

### 5.2 功能清单

- [ ] 将账号从环境变量/私有内存配置迁移为可持久化 `AccountStore`。
- [ ] `AuthUser` 增加 `role`、`status`、`capabilities`；首版角色仍只有 `user`、`admin`。
- [ ] 增加密码版本、失败次数、锁定截止时间、密码修改时间和会话撤销能力。
- [ ] 保持现有 `/auth/login`、`/auth/register`、`/auth/me`、`/auth/usage`、`/auth/logout` 兼容。
- [ ] 管理员创建成员时禁止创建管理员。
- [ ] 封禁、删除、重置密码时撤销目标用户会话。
- [ ] 保护当前管理员和最后一个可用管理员，禁止误删除/误封禁。
- [ ] 后端使用依赖检查角色，前端菜单隐藏不作为安全措施。
- [ ] 保持通用资源接口通过当前用户 ID 做资源隔离；管理员不能因为有角色就自动读取他人任务正文。
- [ ] 不允许 AI Agent、MCP、Skill、Workflow 或模型调用修改角色、额度、审计或升级状态。

### 5.3 API 清单

| 方法 | 路径 | 认证 | 迁移要求 |
|---|---|---|---|
| POST | `/auth/login` | 无 | 保持现有登录协议，返回扩展后的 `user` |
| POST | `/auth/register` | 无/按部署策略 | 只能注册普通用户，首个管理员通过初始化流程产生 |
| GET | `/auth/me` | 本地 JWT | 返回 `id/username/role/status/capabilities` |
| POST | `/auth/logout` | 本地 JWT | 撤销当前会话或令牌版本 |
| GET | `/admin/overview` | admin JWT | 作为管理员权限冒烟接口 |

### 5.4 验收

- [ ] 未登录访问 `/admin/*` 返回 401。
- [ ] 普通用户访问 `/admin/*` 返回 403。
- [ ] 被封禁用户旧 JWT 不能继续访问受保护 API。
- [ ] 重置密码后旧会话全部失效。
- [ ] JWT 中的 `role` 被篡改时，服务端仍以持久化账号为准。

## 6. M2：成员、套餐、订单和额度

### 6.1 功能清单

#### 成员管理

- [ ] 成员分页、关键词、状态、套餐筛选。
- [ ] 创建普通成员：用户名、初始密码、套餐、额外月度 token。
- [ ] 用户名大小写不敏感唯一，3–32 字符，限定字符集。
- [ ] 修改成员状态：正常、锁定、封禁、删除/回收。
- [ ] 修改套餐和额外额度只对增加部分扣减系统池；减少不返还已使用额度。
- [ ] 管理员重置成员密码：原因、当前管理员密码、一次性随机密码、会话撤销、限流、审计。
- [ ] 删除成员时保留消费账本和对账所需记录，清理资源时遵守资源 owner 关系。

#### 套餐与订单

- [ ] 套餐定义包含名称、月度 token、权益、有效状态、版本和来源。
- [ ] 本地管理员只能使用总部下发/配置的套餐，不直接修改套餐价格规则。
- [ ] 订单状态至少包含 `pending`、`completed`、`rejected`、`unknown`。
- [ ] 审批订单必须原子执行：检查 pending、检查用户、扣系统池、更新用户套餐、写账本、更新订单。
- [ ] 拒绝订单不得扣额度。

#### 系统额度

- [ ] 展示 `pool_tokens`、累计充值、测试账号默认额度、成员数和管理员数。
- [ ] 测试账号默认 token 只影响未来新建测试账号，范围 0–100,000,000。
- [ ] 兑换总部签名充值码，校验版本、签名、系统身份、nonce、订单和过期时间。
- [ ] 额度流水追加式记录，不允许修改历史记录；冲正使用反向流水。
- [ ] 余额不足、重复充值、订单状态冲突都返回明确业务错误。

## 7. M3：销售总部连接与充值对接

### 7.1 迁移目标

销售总部与本地系统分属不同数据库。双方只通过 HTTPS + 客户专属 Bearer Token 交换合同规定的数据；`customer_id` 是总部内部客户 ID，`system_id` 是本地助手身份，两者不能混用。

### 7.2 本地功能清单

- [ ] 本地保存 `system_id`、总部 URL、加密 Token、公钥和最后验证状态。
- [ ] GET 配置时 Token 只返回掩码；更新空 Token 表示保持旧值。
- [ ] 独立保存销售总部、技能中心和更新中心配置，不能共用 Token。
- [ ] 发起双向连接验证，分别展示 outbound/inbound 状态。
- [ ] 线上充值走 submit → poll → 本地兑换 → ACK，不把总部审批视为本地到账。
- [ ] 定时同步已审批订单后再上报额度/用量快照。
- [ ] 接收总部远程重置管理员密码命令。
- [ ] 接收总部应用/核心升级命令。

### 7.3 本地管理员 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/sales-hub/config` | Token 脱敏配置 |
| PATCH | `/admin/sales-hub/config` | 更新 URL、Token、公钥、system_id |
| POST | `/admin/sales-hub/verify` | 触发 outbound/inbound 双向验证 |
| POST | `/admin/quota/recharge-requests` | 本地管理员发起线上充值 |
| GET | `/admin/quota/recharge-requests` | 查看本地订单和送达状态 |

### 7.4 本地反向命令 API

| 方法 | 路径 | 必须校验 |
|---|---|---|
| POST | `/integration/sales/v1/ping` | Token → system_id 映射、返回版本和健康 |
| POST | `/integration/sales/v1/admin-password-resets` | 目标必须是本地 admin、操作幂等、密码一次性返回 |
| POST | `/integration/sales/v1/upgrades/{artifact_type}` | 类型、版本、SHA-256、大小、过期时间和下载权限 |

### 7.5 销售总部接口关联

本地 adapter 只调用配套 API 合同中的以下接口：

| 方法 | 总部路径 | 用途 |
|---|---|---|
| POST | `/api/v1/integration/verify-connection` | 上行连接验证并触发反向 Ping |
| POST | `/api/v1/integration/recharge-requests` | 提交充值请求 |
| GET | `/api/v1/integration/recharge-requests/poll` | 拉取已审批订单 |
| POST | `/api/v1/integration/recharge-requests/{order_id}/ack` | 确认本地兑换完成 |
| POST | `/api/v1/integration/usage-reports` | 上报额度/用量快照 |
| GET | `/api/v1/integration/releases/{artifact_type}/latest` | 下载发布包 |
| GET | `/api/v1/integration/public-key` | 获取签名公钥 |

### 7.6 验收

- [ ] 错误 Token、错误 `system_id`、禁用客户均被拒绝。
- [ ] outbound 成功但 inbound 失败时，页面显示部分成功而不是“连接正常”。
- [ ] 重复 submit/poll/redeem/ack 不重复扣款或加额。
- [ ] 报表缺失或上游超时不会伪造为 0 或成功。
- [ ] 总部审批、客户兑换、总部 ACK 三个状态可分别查询。
