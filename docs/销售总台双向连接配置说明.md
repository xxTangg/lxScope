# 销售总台与 AgentScope 管理系统双向连接配置说明

本文说明当前项目如何与新销售总台通过 HTTP API 连接。两套系统不共享数据库，也不依赖旧销售总台。

## 1. 当前已经接入的管理系统接口

销售总台可以使用客户 Token 调用当前管理系统：

```text
POST /integration/sales/v1/ping
POST /integration/sales/v1/admin-password-resets
POST /integration/sales/v1/upgrades/app
POST /integration/sales/v1/upgrades/core
```

其中 `app` 是龙信业务应用，`core` 是 AgentScope 平台整体。

当前升级接口会完成鉴权、参数、有效期、幂等校验并把升级任务放入 Redis 队列，返回 `operation_id` 和 `state=pending`。实际下载、备份、停止、切换、重启、健康检查和回滚，需要按现场运维策略配置升级执行器；HTTP 请求本身不会直接执行 Shell 命令。

## 2. 管理系统调用销售总台的内部管理接口

管理系统登录管理员后，可以调用以下内部接口触发销售总台通信：

```text
GET  /admin/integration/sales/status
POST /admin/integration/sales/verify
POST /admin/integration/sales/usage-report
POST /admin/integration/sales/recharge-requests
GET  /admin/integration/sales/recharge-requests/poll
POST /admin/integration/sales/recharge-requests/ack
GET  /admin/integration/sales/public-key
GET  /admin/integration/sales/releases/app
GET  /admin/integration/sales/releases/core
```

这些是管理系统内部控制接口，不是销售总台调用的外部契约。销售总台外部契约仍然是 `/api/v1`，详见销售总台提供的 `API-CONTRACT.yaml`。

## 3. 环境变量配置

在根目录 `.env` 中填写：

```env
LONGXIN_SYSTEM_NAME=Longxin AgentScope
LONGXIN_SYSTEM_ID=local-system
LONGXIN_APP_VERSION=3.8.1
LONGXIN_CORE_VERSION=2.0.8

# 填写销售总台实际可访问地址，不要使用 127.0.0.1 作为跨机器地址
SALES_CENTER_BASE_URL=https://销售总台内网域名

# 二选一：生产环境推荐使用 Secret 文件
SALES_CENTER_API_TOKEN=
SALES_CENTER_API_TOKEN_FILE=

SALES_CENTER_TIMEOUT_SECONDS=8
SALES_CENTER_VERIFY_TLS=true
SALES_INTEGRATION_ADMIN_USERNAME=admin
LONGXIN_UPGRADE_DIR=/app/upgrade-packages

# 当前汇总上报的基础值；生产环境应替换为真实业务数据来源
LONGXIN_POOL_TOKENS=0
LONGXIN_TOTAL_RECHARGED=0.00
LONGXIN_CUMULATIVE_CREDITS=0
```

`SALES_CENTER_API_TOKEN` 必须是销售总台为本套管理系统生成的客户专属 Token，并且要与 `LONGXIN_SYSTEM_ID` 绑定。Token 不要放到前端、日志、代码仓库或普通聊天消息中。

如果管理系统已经通过原有管理页面保存了销售总部配置，对接层会优先读取 Redis JSON 键 `longxin:sales-hub:v1:config` 中的 `hub_url` 和客户 Token，再使用下面的环境变量作为备用。这样可以与现有管理中心配置保持一致，不需要共享销售总台数据库。

如果使用文件方式：

```env
SALES_CENTER_API_TOKEN_FILE=/run/secrets/sales_center_api_token
```

挂载 Secret 后重建或重启 `agentscope` 服务，使配置生效。

## 4. 两个系统的通信方向

```text
管理系统 ── Bearer Token ──▶ 销售总台
  充值申请、轮询、ACK、用量上报、公钥、升级包下载

销售总台 ── Bearer Token ──▶ 管理系统
  Ping、app 升级、core 升级、管理员密码重置
```

两个方向都必须能访问。若部署在不同容器或不同机器，必须使用真实内网 IP、DNS 或反向代理地址，并配置防火墙和 HTTPS 证书。

当前工作区的本地 Docker 映射为：AgentScope API 对外端口 `8001`，销售总台 API 对外端口 `44100`。这只是当前开发机的测试映射，不能直接当作生产地址；如果两个 Compose 项目分开运行，容器之间应通过宿主机内网地址或统一反向代理访问。

## 5. 配置生效命令

```bash
docker compose up -d --build agentscope
```

查看管理系统健康状态：

```bash
curl -i http://管理系统地址:端口/auth/health
```

使用管理系统管理员登录后，先访问：

```text
GET /admin/integration/sales/status
```

确认 `configured=true` 后，再调用：

```text
POST /admin/integration/sales/verify
```

然后由销售总台使用客户 Token 调用：

```text
POST /integration/sales/v1/ping
```

Ping 成功后再进行用量上报和充值流程联调。
