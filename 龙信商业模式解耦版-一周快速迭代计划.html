解耦原则

商业模式独立开发，AI 引擎只提供能力和用量事件

商业规则不写进 Agent、Session 或模型代码里。商业层通过标准接口获取任务状态和 Token 用量，未来可以替换模型、支付渠道或 AI 引擎，而不重写套餐和账户系统。

01 · CURRENT
lxScope AI 核心Agent、Session、知识库、模型、文件、任务执行。
02 · ADAPTER
任务/用量适配器把 user_id、task_id、状态、Token、耗时和结果文件转换成统一事件。
03 · NEW
商业模式服务账户、套餐、订单、Token 余额、扣费、流水、额度、并发和审计。
04 · UI
用户与管理端购买、账户、任务消费、管理后台、成本和经营看板。

第一版允许模拟

支付可先用模拟购买，套餐价格可先用占位参数，重点是让商业闭环可见。

第一版必须真实

用户身份、任务关联、Token 使用记录和 Token 流水不能只停留在前端假数据。

后续可替换

支付渠道、模型供应商、计费策略和存储方式都通过接口替换，不绑定 Agent 核心。

完整任务清单

商业模式 MVP 要做什么

业务规则

  • 确定 Token 单位和套餐层级
  • 确定套餐价格、Token、有效期和任务量
  • 确定任务开始、成功、失败、重试的扣费规则
  • 确定余额不足、过期和人工调账规则
  • 确定普通会员的并发和任务限制

商业数据

  • 建立用户 Token 账户
  • 建立套餐和订单记录
  • 建立 Token 流水和调账记录
  • 建立任务用量和成本记录
  • 所有记录绑定 user_id 和 task_id

用户端

  • Token 账户首页
  • 套餐展示和模拟购买
  • 任务剩余额度提示
  • 任务完成后的 Token 消耗展示
  • 充值、扣费和退款流水页面

管理端

  • 用户、套餐和 Token 管理
  • 管理员手工赠送或扣减 Token
  • 订单和 Token 流水查询
  • 用户任务量、并发和成本统计
  • 基础操作审计

系统适配

  • 接入 lxScope 当前用户身份
  • 接入当前任务创建和任务状态
  • 按 task_id 记录真实 Token 消耗
  • 创建任务前检查额度
  • 防止重复扣费并验证跨用户隔离

测算和验收

  • 采集真实任务 Token、耗时和失败率
  • 测算单任务模型成本
  • 测算稳定并发和每日任务量
  • 测算普通会员可完成任务数
  • 形成老板演示和第一版经营结论

前 3 天必须交付

先让商业模式跑起来，再谈完整产品化

DAY 1 · 规则和界面

老板看得见

  • 确认套餐、Token 和扣费规则
  • 完成商业总览、套餐、用户账户和管理首页
  • 用模拟数据演示购买、到账和余额
  • 形成商业模式第一版页面
DAY 2 · 接入真实能力

系统接得上

  • 接入当前 JWT 用户和任务
  • 建立账户、订单、流水和任务用量数据
  • 任务完成后记录真实 Token 使用
  • 实现余额展示和基础额度检查
DAY 3 · 完成演示

老板能对齐

  • 模拟购买套餐并完成一次真实任务
  • 展示 Token 扣减、任务成本和流水
  • 展示并发、每日任务量和会员任务量
  • 收集反馈，确认后续一周增强项
第 3 天的验收不是“代码写完了”，而是现场能跑通：管理员配套餐 → 用户获得 Token → 用户做任务 → 系统扣费 → 用户看余额 → 管理员看流水 → 页面给出成本和任务量测算。
第 4～7 天

用真实数据验证，不把商业模式拖到一周后才出现

数据验证

  • 采集不同类型任务的输入、输出 Token 和耗时
  • 区分简单问答、资料分析和文件生成任务
  • 测量稳定并发、失败率和重试成本
  • 校准套餐 Token 额度和预计任务量
  • 输出单任务成本、会员成本和毛利测算

产品增强

  • 完善管理员角色和基础操作审计
  • 补充余额不足、失败、重试和退款处理
  • 增加真实任务结果与用量关联
  • 完善统计看板和导出能力
  • 确定支付、正式订单和企业套餐的后续接口

一周验收

完成标准

老板能看懂打开页面即可看到 Token 购买、套餐、用户使用、管理和成本测算。
用户能使用用户可以获得 Token、创建任务、看到扣费、查看余额和使用流水。
团队能开发商业层通过适配器接入 lxScope，套餐和扣费规则不侵入 Agent 核心。
公司能算账能够用真实任务数据测算单任务成本、并发、会员任务量和套餐毛利空间。
边界要明确真实支付、财务结算、发票、复杂总部管理和正式计费风控作为后续阶段，不影响前三天演示。
最终方案：商业模式在 2～3 天内独立形成可演示 MVP；第 4～7 天接入真实数据、校准模型并补齐产品细节。AI 核心继续演进，但不被套餐、支付和管理逻辑绑死。
